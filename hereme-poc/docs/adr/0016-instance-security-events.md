# ADR 0016: Instance-local security events

Status: Implemented in development, production activation pending controller review (2026-11-24).

SEC-01 adds an instance-local event trail to the existing community application. The current platform registry at `admin.hereme.no` has operational data but no community account database. Security events therefore live beside the account and session facts in each community's SQLite database. The local `operator` role alone receives `security:read`; moderators and ordinary content administrators do not. This differs from presenting all community events in the central platform panel. It preserves per-instance isolation and avoids a cross-community identity database. The platform panel can remain unavailable without disabling community security logging.

Migration 24 retains the earlier small log as `security_events_legacy` and creates `security_events` plus a one-to-one `security_event_raw` table. The shared writer accepts only thirteen fixed event types. It extracts a bounded, explicit subset of request fields, validates the client IP against the loopback proxy boundary, and stores a parsed row with its allowlisted raw snapshot under one SQLite savepoint. Authentication success and account restriction changes are committed with their event rows. A failed required write returns 503 with a sanitized diagnostic; it cannot silently produce an unlogged successful authentication or restriction. Rate-limit rejection is logged once per limiter bucket and window so repeated blocked requests cannot produce unbounded security rows.

The explorer is a read-only tab in the existing staff panel. Server authorization, bounded filters and pagination, HTML escaping and access auditing protect it. The designated `HerEmeAdmin` bootstrap account receives the `operator` role during migration or new staff provisioning; this does not confer log access on every administrator or moderator. The migration records the role grant in the staff audit. IP and browser comparisons are manual observations only; no device identifier, automated cross-account association or automatic sanction is produced. There is no client-side navigation telemetry.
