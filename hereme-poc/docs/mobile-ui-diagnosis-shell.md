# Mobile header and safe-area diagnosis

The supplied iPhone header capture shows six competing controls in one row. In the current shell, the 44 px actions and full `hereme.` wordmark leave little space on a 390 px screen; at 320 px the single-row layout cannot fit all actions at usable touch size. The mobile shell now uses a square Chat icon with an accessible name and keeps the wordmark. At 320–359 px it places actions on a second row instead of shrinking touch targets. Playwright checks 320, 359, 375, 390, and 430 CSS px in dark and light themes, including a visible notification control, and asserts each target fits, stays at least 44 px, and does not overlap. Captures: `screenshots/mobile-ui-fix/wall-header-320.png` and `wall-header-390.png`.

The iOS PWA status-area bleed was not reproducible in desktop Chromium. The existing `viewport-fit=cover` and standalone masthead top padding leave the status inset unpainted after the masthead scrolls away. A fixed, opaque, non-interactive layer now covers only `env(safe-area-inset-top)` in standalone mode, matching the configured dark iOS status bar. Normal Safari has no extra top padding. Scrolling and keyboard behavior in installed iOS Safari/PWA remain **manual / unverified** until checked on a device.

The image tile already reserves a taller face before decode. A true image request failure previously had no distinct UI state, so it could resemble a temporarily empty poster. The poster enhancer now marks loaded/error states, shows a translated failure message over the unchanged tile, and logs each failed URL once. An aborted demo-image browser request verifies the error state while no-image posts keep their separate presentation; capture: `screenshots/mobile-ui-fix/wall-image-error-390.png`.
